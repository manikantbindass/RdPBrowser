# Phase 09 enterprise security console

**PASS for the implemented console and local verification.** Production identity-provider handoff, deployment-specific gateway feed wiring and additional browser/assistive-technology acceptance remain operator checks.

The static admin application now has a responsive navy and cyan interface with keyboard navigation, labeled form controls, confirmation dialogs, accessible tables and a chart with a tabular alternative. The application uses the existing Express/PostgreSQL control plane and Nginx deployment. Existing session termination, account lock/unlock, URL blocks, IP and country activity, alert resolution and tenant-authorized Socket.IO updates are retained.

The console provides organization counts and seven-day UTC security metrics, user creation and subordinate role changes, device key and trust inventory, active sessions, source and gateway health, assigned URL policies, immutable revision history, security events, administrative audit and access decisions, anomaly triage and administrator password settings. No generated live metrics or demo mode is shipped. Browser screenshots below use the clearly named Console verification lab with seeded test records.

Backend additions use tenant RLS and bounded queries. Role updates and account/password operations revoke applicable sessions and write audit entries in the same transaction. A shared role boundary also protects legacy REST and Socket.IO actions. Policy updates persist rules, assignments and a revision snapshot atomically with audit. The API preserves legacy aliases. Existing policies keep organization scope, and older clients that omit assignments retain an existing assignment when editing. Deploy migration 004 and rerun runtime role provisioning with the new build.

Verification passed with 83 backend unit/contract tests, 27 PostgreSQL 15.19 integration tests, three console component/API-client tests and six Chromium browser scenarios. The real database tests cover tenant isolation, ordinary-account denial, privilege boundaries, session and refresh revocation, policy assignment evaluation, adoption of an existing policy revision, immutable snapshots and rollback after audit failure. Chromium exercises desktop and 390-pixel layouts, real mutations and history, hostile device labels, failed API recovery, permission-denied states and current-session termination. Axe found zero violations in the tested overview and policy views. ESLint, runtime JavaScript syntax checks, reproducible 52-path OpenAPI validation and Compose config rendering passed.

The browser signs in through the existing password API and keeps rotating credentials in tab memory. Production MFA and SSO policy remain enforced on the server. A complete OIDC browser-return interface is outside this phase's verified path. Gateway counts require an operator-published status file, remain tenant filtered and report missing or stale observations. Handshake activity and accepted source checks have the boundaries described in the network guide. Physical-device browsers, screen readers and live organization deployments were not exercised.
