# Phase 13 automated verification

**Status: PARTIAL.** Functional verification, security scans and performance checks now have reproducible commands and evidence. Open security gates and unverified platform coverage prevent release acceptance.

Phase 13 started from `9d4020ca9ff20a17c20d3d1552558dd96d439bbf`. The previous GitHub runs passed architecture and desktop checks. Network tests failed because the Ubuntu Nginx package did not support the Docker upstream `resolve` parameter. The deployment drill failed because the hosted runner’s temporary runtime path was hidden inside the private `/run` mount. Android CI stopped before compilation because `sdkmanager` was missing. The changes adapt the native loopback fixtures to older Nginx, set writable runtime paths inside isolated Docker namespaces and install Android command-line tools explicitly. Production dynamic DNS and the existing VPN firewall remain enforced. The prior failures are documented in the [network run](https://github.com/manikantbindass/RdPBrowser/actions/runs/44107364659), [deployment run](https://github.com/manikantbindass/RdPBrowser/actions/runs/44107364843) and [Android job](https://github.com/manikantbindass/RdPBrowser/actions/runs/44107364969/job/134123870763).

The desktop login now provides a main landmark, announces errors and keeps text contrast above the automated threshold. The new real-bundle browser tests cover keyboard focus, narrow layout, accessibility and the refusal to submit credentials without native IPC. The backend bounds and validates country-code lists without the flagged repeated regular expression. GeoIP now uses 2.0.3, which removed the two previously recorded production npm advisories. That version requires Node 24, so the backend documents the runtime requirement and aligns its CI and Docker image. The Rust lockfile updates `quinn-proto` and the current `rustls-webpki` dependency within their existing compatibility ranges. The pinned Nginx base moves to 1.30.6. No authentication, routing, database or release signing checks were relaxed to obtain a pass.

CI now retains scan artifacts and reports failures from dependency, source, static and runtime-image checks. It no longer forces Jest to exit or suppresses the selected security checks. The deployment workflow checks measured load and recovery thresholds. The architecture workflow builds the desktop frontend and runs its UI checks alongside the console. ## Release gates

The [redacted scanner summary](audit/phase13/security-summary.json) records affected packages, severities and source locations without capturing matched secrets or source snippets. The simple signature scan passed. Gitleaks returned 30 candidates in the repository snapshot, including generated verification hashes and test fixtures. Candidates remain visible for review. The static analyzer shifted from 53 findings to 52 after the country-code validator changed. The remaining 25 filesystem-path and 27 dynamic property reports require review. Scanner counts may repeat an advisory across packages or platforms.

The patched backend image has six high findings and the patched edge image has three high findings. Both scans report zero critical findings. The previous edge image had three critical and 73 high findings. The source scan also retains two high and six critical instances across Rust dependencies and DigitalOcean ingress and egress rules. Review the cloud rules against the public WireGuard listener and gateway forwarding requirements before any deployment.

The current Tauri updater pins a ZIP dependency whose affected major has no compatible scanner-reported fix. Upgrading it requires an upstream-supported dependency range or a separately verified updater migration. Signed installer/update acceptance, physical Android devices, native macOS/Linux UI, assistive-device testing, and deployed provider, VPN and cloud acceptance also remain open. The contained load results set a regression gate for the small fixture. The hosted APK build initially failed on a retired SDK package. Commit `041e4b0` pins the Android SDK setup action that installs `platform-tools`. The corrected job passed analysis and tests, built release-mode APKs for ARMv7, ARM64 and x86-64, and passed signature and alignment verification with the CI key. Both the Android failure and separate baseline failures remain documented.
